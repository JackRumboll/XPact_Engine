XToolchainContract

Stub. This is the Step 0 deliverable per master-plan Section 4. It is an interfaces-only contract for the three toolchain systems — XBT, XHT, XIL2CPP — designed jointly before any of them gets its own spec. The contract locks interfaces; internals are deferred to each tool's own spec. Section bodies below are empty and will be filled in by the Step 0 design task.

1. Reflection Schema

Name table, marker macros, surface vocabulary. Full binary schema (FName / FClass / FProperty / FField layout including all replication slots) is deferred to a versioned addendum locked at XCore-4b. XHT's parser ships at step 2; XHT's emit format is frozen at the addendum.

2. Hot-Reload Symbol Naming

Stable exported names for hot-patchable functions, versioned vtable layout, patch-DLL discovery protocol.

3. GC Root-Registration ABI

What the IL2CPP transpiler emits for non-GC containers holding XObjects; the runtime ABI for register / de-register; handling of List<object> and other non-statically-typed containers (conservative full-slot registration).

4. Determinism Flag Propagation

How a module declares "this TU is sim-path"; how XBT translates that to /fp:precise + -ffp-contract=off + transcendental-library substitution at compile time.

5. Exception Codegen Switch

The ABI-stable boundary layer that gives transpiled C# functions identical external signatures across Dev (native exceptions) and Shipping (Result<T,E>); internal-only differences in lowering.

6. C# String ↔ FString Mapping

C# string transpiles to an immutable string handle wrapping FString (UTF-8); literal C# strings emit as UTF-8 byte arrays at transpile time (no runtime conversion); foreach over a C# string iterates code points, not bytes.

XHT Emit-Format Freeze — Two-Stage

XHT's emit format is frozen in two stages. Step 0 (this document) locks the interface; the binary schema is frozen later at the Contract addendum that lands when XCore-4b ships at Step 4.

Stage A — Step 0 (this document): Interface Freeze

Locks file naming, invocation protocol, marker macros, and surface vocabulary. XBT consumes XHT output opaquely — XBT does not parse XHT's binary struct layouts — so XBT at Step 1 is decoupled from the binary-schema finalization in Stage B.

Stage B — Step 4 Contract Addendum: Binary-Schema Freeze

Lands when XCore-4b ships. Freezes the concrete output struct layouts (FName / FClass / FProperty / FField including all replication-metadata slots). XHT Step 2 ships parser-complete + emitter-provisional; XHT's emitter finalizes its concrete output struct layouts here.

Pending: Per-File Dependency Model (TBD at XBT Implementation)

Per master-plan Section 4: the contract carries explicit "TBD at XBT implementation" markers for the per-file dependency model, which can only be hardened once XBT is built. The Step 0.5 addendum (descriptive) will document the per-file dependency model that XBT actually implements, rather than prescribing one ahead of time. The Step 0.5 addendum does not change XBT's behavior; it pins the model XBT chose so XHT and XIL2CPP can target it.
