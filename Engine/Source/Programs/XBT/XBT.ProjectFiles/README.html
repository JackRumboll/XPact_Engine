XBT.ProjectFiles

IDE project-file generation for XBT per /Documents/XBT.html Rev 4 Section 14. MVP generators are clangd and JetBrains Rider; Visual Studio and Xcode are Phase 2.

Lazy generation (footgun #9 preempt). UBT regenerates project files for the full cross-product of targets × platforms × configurations, which is slow at XPact scale (3 targets × 3 platforms × 5 configurations × ~200 modules). XBT instead generates project files only for the target the IDE has selected, identified by the CLI flags passed to GenerateProjectFiles. The first invocation per session generates; subsequent invocations of the same target are cached.

Public surface:

  • IProjectFileGenerator — one interface every generator implements. GenerationContext carries the active TargetRules, the discovered module + plugin catalogs, and the toolchain. GenerationResult reports which files were written + a single error message on failure.
  • ClangdCompileCommandsGenerator — emits <EngineRoot>/compile_commands.json per the LLVM JSON Compilation Database spec. Per Section 14.3: one entry per .cpp in every module enabled by the target, with the full compile-command vector. MSVC-style flags (/D, /I) translate to Clang-style (-D, -I) since clangd is Clang; reproducibility-envelope flags pass through unchanged.
  • RiderProjectGenerator — emits a minimal .idea/ tree at <EngineRoot>/.idea/: modules.xml, one .iml per XPact module, workspace.xml, and .gitignore. Rider's build action delegates back to XBT.exe build per Section 14.4 / UBT's pattern.

Determinism. Both generators emit byte-identical output across re-runs given identical input. Tests in XBT.Tests assert this invariant.
