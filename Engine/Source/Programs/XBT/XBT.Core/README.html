XBT.Core

Primitives shared across the other XBT modules. No build semantics live here — ActionGraph, descriptor parsing, toolchain abstraction all sit in higher-layer XBT modules that depend on XBT.Core.

Per /Documents/XBT.html Section 2: "FileItems, content-hashing (BLAKE3 via vendored library), atomic file IO with pinned temp-file naming, sorted-set utilities, structured logging helpers, streaming JSON channel writer. No knowledge of build semantics."

Phase 1 surface (this commit):

  • IoHash — 32-byte BLAKE3 content-addressable digest. Mirrors UE's IoHash.cs in shape but is a XPact-original implementation.
  • FileItem — cached descriptor for a tracked file: path, length, modification timestamp (informational only), lazy content hash.
  • Logger — minimal stderr+stdout sink with a reservation for the streaming JSON channel of /Documents/XBT.html Section 21.2 (Phase 1.1 work).
  • CancellationExt — helpers for the CancellationToken propagation contract of /Documents/XBT.html Section 20.3.

Atomic file IO with pinned temp-file naming (<output>.tmp.<pid>.<actionid>) is a later add — that surface lands when XBT.ActionGraph appears in Phase 1.2. The shape is foreseen in this README so the API can be introduced without restructuring the module.
