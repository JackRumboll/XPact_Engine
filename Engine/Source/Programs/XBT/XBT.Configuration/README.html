XBT.Configuration

The descriptor surface for the XPact Build Tool. Owns the in-memory ModuleRules and TargetRules POCOs, the .Build.toml parser (Tomlyn-backed), the sandboxed Starlark-subset expression evaluator for .Build.expr files, the IBuildHook interface, and the cross-tier dependency matrix enforcer.

Per /Documents/XBT.html Rev 4 Section 4 and Toolchain Contract Rev 13 Section 9 ("Module Descriptor Shape").

Public surface (Phase 1.2):

  • ModuleRules, TargetRules — in-memory descriptors. Field-for-field mirror of the contract surface; consumed by XBT.ActionGraph and XBT.Toolchain.
  • IBuildHook, BuildHookContext — typed pre/post-build hook surface per Contract Section 9.5. Hooks return IExternalAction instances (owned by XBT.ActionGraph) so they participate in the action graph as first-class nodes — cacheable, incrementalizable, parallelizable.
  • TierMatrix + TierValidator — cross-tier dependency-edge matrix per Contract Section 9.3 and XBT.html Section 13.1. Link deps point downward (Engine ← Studio ← Project); DynamicallyLoadedModuleNames may point upward.
  • BuildTomlParser + BuildTomlSerializer — round-trip TOML I/O. Strict parse rejects unknown top-level keys (closed surface, exit 30). Deterministic ordering on write.
  • PluginDescriptor + PluginDescriptorParser — .xplugin POCO and JSON parser. The JSON form mirrors UE's .uplugin with XPact-specific fields.
  • StarlarkEvaluator — sandboxed subset evaluator for .Build.expr per Contract Section 9.6. 100,000 instruction budget; no file I/O, no recursion past 32 frames, no mutation, no def.

Tomlyn dependency. Pinned at 0.17.0 (latest stable 0.17.x). Small (~150 KB) pure managed parser producing a typed DOM. Used only by BuildTomlParser; the rest of XBT.Configuration operates on POCOs.

No engine-runtime imports. Pure tooling code; only references XBT.Core (primitives) and XBT.Manifest (shared enums + ModuleDep).
