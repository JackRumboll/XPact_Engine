XBT — XPact Build Tool

XBT is the build orchestrator for every XPact build — the C# .NET 8 standalone executable that discovers modules, builds the dependency graph, invokes XHT (reflection extraction) and XIL2CPP (C# transpilation), schedules compile and link actions, and emits the JSON + FlatBuffers manifest that downstream tools consume. It is Layer 0 (Build & Tooling), tier Engine, and the first system implemented after the Toolchain Contract. Reference spec: /Documents/XBT.html Rev 4; interface contract: /Documents/XToolchainContract.html Rev 13.

Module layout

XBT itself is a multi-project C# solution living under this directory. Each sub-project has a small, named purpose so subagent work can be split cleanly per /Documents/XBT.html Section 2:

  • XBT.Core — primitives shared across the other XBT modules: content-addressable IoHash (BLAKE3), tracked FileItem, structured logging, cancellation extensions. No build semantics.
  • XBT.Manifest — manifest DTO types serialisable both as JSON (System.Text.Json) and as the FlatBuffers binary sidecar defined in Toolchain Contract Section 10.2. Referenced by XHT and XIL2CPP at their build time so all three tools share one set of DTOs. The FlatBuffers schema (Manifest.fbs) and the contract version derivation are owned by this module.
  • XBT.Entry — the executable. Owns Main, the CLI parser, the mode dispatcher, and the built-in modes (Help, Version, Build, QueryTargets, …). Implements UBT's IToolMode<T> pattern with C# 12 static-abstract members.
  • XBT.Tests — sibling test module covering all of the above (added by Subagent B; see /Documents/XBT.html Section 22).

Three further sub-modules called out in /Documents/XBT.html Section 2 (XBT.Configuration, XBT.ActionGraph, XBT.Executor, XBT.Toolchain, XBT.ProjectFiles, XBT.LiveCoding, XBT.Discovery) are Phase 1.2 work — the bare-bones foundation in this Phase 1 deliverable does not need them to produce a working XBT.exe Version / XBT.exe Help binary.

How to build

Per the master plan's auto-memory reference to the build system: production XBT builds go through XBT.Build bat scripts once they exist. Until then, the .csproj solution at XBT.sln is a stand-alone dotnet-buildable unit: dotnet build Engine/Source/Programs/XBT/XBT.sln from the repo root produces the XBT.Entry executable plus the two class-library dependencies. The build is deterministic (warnings-as-errors, <Deterministic>true</Deterministic>, embedded sources) per Toolchain Contract Rev 13 Section 2.1.
