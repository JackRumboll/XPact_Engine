XBT.Toolchain

The platform-toolchain abstraction layer for the XPact Build Tool. Translates module-level enums (FPSemantics, OptimizeCodeMode, SimdLevel, SimPath) into the per-platform flag sets MSVC and Clang accept. Constructs the IExternalAction instances for compile and link.

Per /Documents/XBT.html Rev 4 Sections 7 (Toolchain Abstraction), 19.1 (Reproducibility Envelope) and Toolchain Contract Rev 13 Section 4 ("Determinism Flag Propagation") + Section 5 ("Exception Codegen Switch").

Public surface (Phase 1.2):

  • XToolChain — abstract base. Owns the CompileSource, LinkModule, GetCompileArguments_FPSemantics, GetCompileArguments_OptimizeCode, GetCompileArguments_Simd, GetCompileArguments_SimPath seams.
  • XMSVCToolChain — concrete subclass for Win64. Discovers MSVC via vswhere.exe (cached). Emits the unconditional reproducibility envelope (/Brepro, /BREPRO, /TIMESTAMP:0, /pathmap:<RepoRoot>=X:/R, /INCREMENTAL:NO, /d2:-cgmanifestencoded-). SIMD lever maps to /arch:<level>; SimPath modules force /fp:precise + the ≤SSE42 ceiling.
  • XClangToolChain — concrete subclass for Linux and Android. Discovers Clang via $LLVM_HOME or $ANDROID_NDK_ROOT. Emits the reproducibility envelope (-fdebug-prefix-map, -fno-ident, -Wl,--build-id=none, -fdeterministic-cgu-order). SimPath modules force -ffp-contract=off + -mno-fma; the -include XSimPathMathOverrides.h header gate is injected by XBT (the header file itself lands in a later phase).
  • VCEnvironment — the cached MSVC discovery record (CompilerPath, LinkerPath, include paths, lib paths, Windows SDK version). Mirrors UE's VCEnvironment.

Subagent A coordination. The toolchain code consumes ModuleRules and TargetRules from XBT.Configuration. Until Subagent A's project surfaces those types, the toolchain uses placeholder POCOs declared in the Simgenics.XPact.XBT.Toolchain._Placeholders namespace whose field set matches XBT.html Rev 4 Section 4.2 verbatim. When A's types land, the placeholders are removed and the toolchain repoints at XBT.Configuration's real types — the field-set contract is identical, so no API changes ripple downstream.
