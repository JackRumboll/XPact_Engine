XBT.Manifest

Manifest DTO types shared between XBT (writer) and XHT / XIL2CPP (readers). Per /Documents/XToolchainContract.html Rev 13 Section 10.2, every XBT build emits the manifest in two forms in lockstep:

  • JSON (this Phase 1 commit) — human-readable, diffable in version control, parsed via System.Text.Json with hardened reader options per /Documents/XBT.html Section 8.4 (max depth 64, max bytes 100 MB, max array 65,536, max string 16 KB).
  • FlatBuffers binary sidecar — added by Subagent B alongside Manifest.fbs. Loaded zero-copy by XHT and XIL2CPP at run time.

The C# DTOs here (ManifestSchema.cs) mirror the FBS schema field-by-field; Subagent B's tests verify enum ordinal alignment between the C# enums in Enums.cs and the FBS append-only enum ordinals in Manifest.fbs.

Per Toolchain Contract Rev 13 Section 10.2 the FBS ModuleType enum is append-only and Rev 13 appended Programs at ordinal 4 after ThirdParty (ordinal 3). The C# enum in this module preserves the same ordering so default JSON serialization round-trips against FBS without re-ordering surprises.
