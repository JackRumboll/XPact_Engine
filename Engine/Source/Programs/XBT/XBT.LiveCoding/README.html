XBT.LiveCoding

Phase-1 interface seams reserved for Phase-2 XLiveCoding integration per /Documents/XBT.html Rev 4 Section 16 ("Live Coding Hook"). Phase 1 ships the interface shapes and the no-op defaults; nothing in Phase 1 calls into them in anger -- the patcher registry is empty, no quiesce participants register, and no patch DLLs are produced.

Public surface:

  • IActionGraphPatcher — per-toolchain hook that mutates the action graph after Link()+Sort() but before executor dispatch. Routes through the originating toolchain class (NOT through executable-name string matching; preempts UE footgun #5). Phase 1 ships the contract, Phase 2 XLiveCoding plugs in XLiveCodingPatcher which rewrites Compile actions (.obj → .lc.obj, response file extension → .lc.response, dependency file path).
  • PatcherContext — the per-call context passed to every patcher (active TargetRules, engine root path, diagnostic logger channel).
  • PatcherRegistry — mutable list of registered patchers. BuildMode calls ApplyAll between the action-graph sort and the executor dispatch. Empty registry = no-op (Phase 1 default).
  • IQuiesceParticipant — participant in the Phase 2 hot-reload cascade's function-pointer-write window. Quiesce + resume on a fixed priority order (QuiescePriority).
  • QuiescePriority — the strict ordering for the cascade. Rev 3 fix: GC marker threads quiesce FIRST (priority 0), not last, so no concurrent mark phase observes a function pointer mid-rewrite. Then game thread, render thread, RHI thread, audio thread, loading threads, sim-path worker pool (priority 6) in that order. On resume the order reverses.
  • PatchDllDiscovery — static helpers that scan /Intermediate/Build/<Target>/<Configuration>/LiveCoding/<Module>.patch.<gen>.dll for the next per-(Target, Module) generation counter. Per Section 16.7 the counter persists by scanning observed files (not a separate persistence file). Phase 1 implements the discovery; Phase 2 XLiveCoding writes the DLLs.

Phase 1 is interface-only. No DLLs are produced, no patchers are registered, no quiesce participants are registered. The seams exist so the Phase 2 XLiveCoding integration does not require retrofitting XBT.
